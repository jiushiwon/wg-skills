# deploy-profile.md 格式规范

`deploy-profile.md` 是 `deploy-detect-skill` 的输出，也是 `server-setup-skill`、`static-nginx-skill`、`deploy-native-skill`、`deploy-docker-skill` 共享的输入。结构必须稳定。

## 固定结构

```markdown
# 项目部署画像

## 项目信息
- 项目根目录：<绝对路径>
- 检测时间：<YYYY-MM-DD>
- 检测人：<user | claude>

## 检测到的技术栈
| 类型 | 识别结果 | 置信度 | 依据文件 |
|------|----------|--------|----------|
| 语言 | <语言 + 版本> | <高/中/低> | <文件路径> |
| Web 框架 | <框架 + 版本> | <高/中/低> | <文件路径> |
| 前端构建产物 | <有/无 + 目录> | <高/中/低> | <目录路径> |
| 数据库 | <类型 + 版本> | <高/中/低> | <文件路径> |
| 缓存 | <类型 + 版本> | <高/中/低> | <文件路径> |
| 消息队列 | <类型 + 版本> | <高/中/低> | <文件路径> |

## 推断的部署需求
- 需要运行时：<语言 + 版本，多个用逗号分隔>
- 需要数据库：<数据库 + 版本，注明是否待用户确认>
- 需要缓存：<缓存 + 版本，或「无」>
- 需要消息队列：<组件 + 版本，或「无」>
- 需要反向代理：<是（前端产物）/ 否>
- 应用端口（APP_PORT）：<端口号，默认 8080；SSR/前端静态项目标 80/443>
- 建议部署方式：<原生 / Docker / 均可>
- 备注：<用户确认的特殊说明>
```

### 端口约定

端口统一用环境变量 **`APP_PORT`**，贯穿启动脚本、systemd/pm2、Dockerfile EXPOSE、Nginx `proxy_pass`。识别时按以下默认推断，用户可覆盖：

| 项目类型 | 默认 APP_PORT | 备注 |
|----------|--------------|------|
| Node.js / Python / Java / Go 后端 | 8080 | 可被 `.env` 或命令行覆盖 |
| Next.js / Nuxt（SSR） | 3000 | Nginx 反代到 3000 |
| 纯静态 / SPA（Nginx 托管） | 80 / 443 | 应用本身不监听端口，Nginx 监听 |

详细规则见 `deploy-native-skill/references/script-standards.md` 的「端口约定」。

## 字段含义

### 项目信息

- **项目根目录**：扫描时使用的绝对路径，下游 skill 据此定位项目。
- **检测时间**：用于判断画像是否过期；项目变更后应重新检测。
- **检测人**：区分是用户手动触发还是 Claude 自动触发。

### 技术栈表格

- **类型**：固定枚举（语言 / Web 框架 / 前端构建产物 / 数据库 / 缓存 / 消息队列）。
- **识别结果**：名称 + 版本；无法确定版本时只写名称。
- **置信度**：高 / 中 / 低，决定下游是否需要二次确认。
- **依据文件**：触发识别的文件或目录路径，便于复核。

### 部署需求

- 由技术栈表格汇总而来的「部署视角」结论。
- 中/低置信度项必须注明「待用户确认」。
- 「需要反向代理」：前端产物命中时为「是」，纯后端服务为「否」。
- 「建议部署方式」：根据项目体量、是否有 Dockerfile、是否多服务给出建议。

## 置信度判定标准

| 置信度 | 条件 |
|--------|------|
| 高 | 标志性文件存在且依赖声明明确（如 `package.json` 含 `express`） |
| 中 | 通过配置文件推断（如 `.env` 含 `DB_URL=postgres://`） |
| 低 | 源码出现关键字但依赖未声明（如 `import redis` 但 `package.json` 无 redis） |

## 多语言 / monorepo

每个子目录输出一个独立小节：

```markdown
## 子项目：apps/api（Node.js）
| 类型 | 识别结果 | 置信度 | 依据文件 |
| ... |

## 子项目：apps/web（Vue）
| 类型 | 识别结果 | 置信度 | 依据文件 |
| ... |
```

下游 skill 按子项目分别处理。

## 兼容性

- 字段缺失时填「未检测」或「N/A」，禁止编造。
- 新增字段必须同步更新本规范，并在下游 skill 中做好容错（缺失字段视为「未检测」）。
