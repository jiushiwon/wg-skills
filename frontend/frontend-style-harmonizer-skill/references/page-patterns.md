# 页面模式审查规则

页面模式用于防止“每个页面都重新发明一套列表页或表单页”。它只比较同一项目内同一语义模式，不要求营销页和后台页强行统一。

| 页面模式 | 必查区域 | 常见漂移 |
|---|---|---|
| 列表页 | 页面 gutter、头部、搜索/筛选、工具栏、列表/表格、分页、空/加载/错误 | 根容器与卡片混用 padding/margin、搜索框高度和图标不同、空状态缺失 |
| 表单页 | 页面 gutter、标题、表单项、说明/校验、固定操作区、取消/提交顺序 | label 宽度不同、错误间距不同、键盘遮挡提交按钮 |
| 详情页 | 标题区、摘要、信息分组、操作区、返回入口 | 卡片间距、分割线、标题层级不同 |
| 设置页 | 分组标题、Cell、Switch/Checkbox、危险操作区 | 行高、右侧控件、危险色使用不一致 |
| 登录/认证页 | 品牌区、字段、协议、提交、第三方入口 | 输入高度、错误反馈、禁用态不同 |
| 移动端底部操作页 | 内容安全区、固定操作区、按钮组、键盘策略 | 内容被遮挡、按钮高度和 safe-area 不同、键盘重复顶起 |

## 审查步骤

1. 先按路由、文件名、页面标题和结构识别模式，置信度不足时标注“待确认”。
2. 只在同一模式内比较：例如列表页的搜索框互相比较，不与登录框互相比较。
3. 结构差异先判断是否业务必要；只有视觉层相同语义的差异才进入收敛计划。
4. 发现重复模式时，建议抽公共 Layout / Slot / Variant，不直接复制整页。
5. 对页面外侧 gutter、卡片 padding、模块间距、固定区预留分别记录责任方；视觉相近但责任不同必须作为实现漂移报告。

## 页面状态检查

| 状态 | 最低检查项 |
|---|---|
| loading | 是否有占位、禁用或加载反馈；避免空白闪烁 |
| empty | 是否有说明、恢复路径或主操作；不同页面是否复用同一空状态组件 |
| error | 是否可理解、可重试，错误色/间距是否遵循 Token |
| permission | 无权限与“没有数据”是否区分，避免误导 |

## 例外规则

Hero、活动落地页、数据大屏、编辑器、第三方嵌入允许特殊布局。报告应记录“页面 + 例外范围 + 原因”，而不是以“风格不同”作为自动豁免。
