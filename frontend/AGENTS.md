# 前端公共规范

> 上位规范：仓库根 `AGENTS.md`。下位规范：各 Skill 目录的 `STANDARD.md`。

## 职责边界

| 事实 | 唯一负责方 | 其他 Skill 的使用方式 |
|---|---|---|
| agent-qa 已有运行与 memidex 来源审查 | `agent-qa-skill` | 只读核对运行证据，不重跑测试或修改状态 |
| Vue 设计 Token | `vue/vue-theme-skill` | 只引用、审查，不新造平行 Token |
| Vue 样式基础设施 | `vue/vue-style-skill` | 只引用其布局、动效与工具类规则 |
| Vue 基础组件 | `vue/vue-base-skill` 及子 Skill | 复用组件，不复制实现 |
| uni-app 主题与变量 | `uniapp/uniapp-theme-skill` | 只引用、审查，不重定义同名变量 |
| uni-app 设计系统与组件规则 | `uniapp/uniapp-style-skill`、`uniapp/uniapp-base-skill` | 复用组件和 Token |
| 跨页面一致性审查 | `frontend-style-harmonizer-skill` | 只审查、报告、经确认后做视觉层收敛 |
| 移动端安全区与键盘审计 | `mobile-safe-area-audit-skill` | 聚焦顶部胶囊、底部安全区、固定区与键盘；确认基线后最小修复 |
| 移动端 UI/UX 设计与交付基线 | `mobile-uiux-spec-skill` | 设计稿单位、触控/排版、跨端 Variant、鸿蒙折叠态和交付验收；不改业务项目 |

## 公共规则

1. 项目已有主题 Token、公共组件或 UI 库时，新增页面必须优先复用；禁止仅为单页效果复制一套近似实现。
2. 同一项目的同语义组件必须遵守同一组件契约：来源、尺寸阶梯、圆角、交互状态、图标位置和无障碍语义不可随页面自行漂移。
3. 页面例外（营销 Hero、沉浸式活动、数据可视化等）必须在审查报告中说明原因；例外不是默认豁免。
4. 一致性审查默认只读。只有用户确认基线与 diff 后，才可执行视觉层修复。
5. 审查 Skill 不得修改业务状态、事件、接口、路由、权限或文案逻辑。
6. 页面空间系统（页面外侧 gutter、模块间距、顶部导航偏移、固定底栏内容避让、安全区与键盘顶起）属于跨页面一致性的一部分；视觉相近但实现基线不同，必须在报告中单独标注。
7. 图标属于语义契约：同一业务动作在同一产品域内必须优先复用同一图标资产、尺寸、颜色状态与点击区域；颜色或图形差异只有在状态或危险等级明确不同的情况下才可作为例外。

## 变更纪律

- 改 Token → 对应主题 Skill；改公共组件 → 对应组件 Skill；改跨页面规范 → 一致性审查 Skill 的参考资料。
- 新增通用组件类型，先补组件契约，再在具体组件 Skill 中实现。
- 所有自动修复必须保留框架和项目现有组件方案，不得擅自换 UI 库。
- 移动端设计基线不是运行时安全区的替代品：设备状态栏、微信胶囊、键盘和避让区必须由运行时值或端侧 API 决定；设计稿只定义结构与责任。
