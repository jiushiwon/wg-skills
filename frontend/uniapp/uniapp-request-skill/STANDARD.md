# uniapp-request-skill 个体规范

> 上位规范：[uniapp/AGENTS.md](../AGENTS.md)
> 本文件只写本模块特有约束；与上位规范重复的内容不再赘述。

## 一、模块定位

**第 2 层：专项层（数据请求）。**

本模块负责 uni-app 小程序的**请求层实现**：封装、拦截器、错误处理、重试、取消、上传下载、并发控制。

> **边界**：接口**约定**（响应信封 `{code,message,data}`、错误码语义、Mock key 格式 `METHOD:相对路径`、API 前缀 `/api`）归 `uniapp-standard-skill`；本模块只负责**实现与使用规范**，不得另立一套信封定义。

## 二、依赖

| 依赖 | 方向 | 用途 |
|------|------|------|
| `uniapp-standard-skill` | 依赖（前置规范） | 接口约定、红线 R17 / R09 / R10 |

## 三、目录约定

本模块描述使用方项目里的请求层落位：

```
src/
├── api/            # 接口定义（函数签名 + 路径 + 参数类型）
├── services/       # 业务服务（数据编排）
└── utils/request/  # 请求封装实现
```

- 业务页面**只调 `api/` 里的函数**，不直接调 `uni.request`。
- `api/` 只描述"调什么"，`services/` 负责"怎么组合数据"。

## 四、内容清单

| 章节 | 内容 |
|------|------|
| §1 请求封装 | 统一入口、参数签名 |
| §2 拦截器 | 请求 / 响应拦截、Token 注入 |

## 五、内置约束

**Q01** 响应信封固定 `{ code, message, data }`，与 `uniapp-standard-skill` 一致，本模块不得自定义。

**Q02** API 前缀统一 `/api`；业务侧只传相对业务路径。

**Q03** 错误处理必须覆盖：网络异常、超时、业务错误码、鉴权失效（401）、服务端 5xx。每类都要有明确的**用户可见行为**（R10：失败必须弹提示）。

**Q04** 401 不得直接抛错到页面，必须走统一登录态刷新流程；并发 401 只触发一次刷新。

**Q05** 列表类请求必须内置分页参数与"加载更多/上拉刷新"配套的状态位。

**Q06** 提交类请求（POST/PUT/DELETE）必须防重复提交。

**Q07** 请求失败要写日志（可定位：接口、参数、错误码），不得静默吞异常。

**Q08** 组件内**禁止**发起请求（与 `uniapp-page-components-skill` P12 一致），数据由外部传入。

**Q09** 认证相关请求归 `uniapp-auth-skill` 收口（R20），本模块不实现登录逻辑，只提供注入点。

## 六、变更纪律

- 改信封/前缀/错误码语义 → 同步 `uniapp-standard-skill` §4 与 `uniapp-code-audit-skill` 的 API 契约维度映射。
- 改拦截器行为 → 同步 `SKILL.md` 与 `README.md` 示例。

- [ ] API 前缀只有一套写法
- [ ] 每类错误都有用户可见行为
- [ ] 提交类请求有防重
