# UniApp 会员中心与积分商城

生成“会员身份 + 权益 + 积分任务 + 商品兑换”场景页。先复用项目已有规范，再组合业务区块；不得为页面另建主题、请求封装或基础组件体系。

## 必须依赖

| 能力 | 依赖 Skill | 本页使用方式 |
|---|---|---|
| 项目结构与命名 | `uniapp-standard-skill` | 页面目录、分页、组件通信遵循其规范 |
| 主题变量 | `uniapp-theme-skill` | 使用 `var(--primary-*)`、`var(--text-*)`、`var(--bg-*)`、`var(--radius-*)` |
| 视觉规范 | `uniapp-style-skill` | 遵循文字层级、间距、触摸区、图片兜底与对比度规则 |
| 基础组件 | `uniapp-page-components-skill` | 优先组合 `base-card`、`base-avatar`、`base-button`、`empty` |
| 数据请求 | `uniapp-request-skill` | 页面容器负责请求；展示组件只接收数据并 `emit` 事件 |

项目无主题系统时先调用 `uniapp-theme-skill`；无基础页面组件时先调用 `uniapp-page-components-skill`。禁止为了赶效果写死颜色、圆角、间距或重复实现请求逻辑。

## 输出范围

1. 会员头：身份、等级、积分、权益入口。
2. 权益区：3~4 个可配置权益，不把业务文案写死进组件。
3. 每日任务：进度、任务列表、领取状态。
4. 积分商城：两列商品卡，支持加载、空态、图片错误兜底。
5. 页面状态：加载骨架、空态、请求失败、未登录跳转。
6. 数据契约：会员、任务、商品三个 DTO；具体业务后端自行实现。

## 实施顺序

1. 读取主题变量与现有基础组件；缺失时先补依赖。
2. 在页面容器通过 request-skill 请求数据；把 `member`、`tasks`、`products` 传给展示组件。
3. 以 `templates/member-center.vue` 作为结构基线，替换 mock 数据。
4. 点击操作只发出 `benefit`、`task`、`product` 事件；导航与接口副作用留在页面容器。
5. 按 `references/acceptance.md` 验收四种数据状态和小程序安全区。

## 禁止项

- 禁止引入 uView、Vant、ColorUI 等第三方 UI 库。
- 禁止把积分、等级、商品、任务名称写死为生产数据。
- 禁止组件内部直接调用 `uni.request`。
- 禁止脱离主题变量复制视觉稿中的固定绿色、金色、圆角和阴影。
- 禁止只做默认态；必须提供加载、空、失败、未登录处理。

视觉参考见 `assets/member-center-premium-reference.png`；它只定义信息层级和质感目标，不能作为像素级抄图依据。
