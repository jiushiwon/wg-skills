# uniapp-crossplatform-audit-skill 个体规范

> 上位规范：[uniapp/AGENTS.md](../AGENTS.md)
> 本文件只写本模块特有约束；与上位规范重复的内容不再赘述。

## 一、模块定位

**第 2 层：专项层（跨端兼容审计）。**

本模块审计 uni-app 项目在各端（微信小程序 / 支付宝 / 抖音 / H5 / App / 鸿蒙）上的**兼容性问题**：平台专属 API、条件编译、样式差异、组件差异、性能差异。

> **边界**：与 `uniapp-code-audit-skill` 的分工是"通用规范"与"跨端差异"。本模块不看通用红线，只看跨端。

## 二、依赖

| 依赖 | 方向 | 用途 |
|------|------|------|
| `uniapp-standard-skill` | 依赖（前置规范） | R19 鸿蒙降级、目录与命名 |
| `uniapp-code-audit-skill` | 平行 | 输出形式对齐（报告结构、风险分级） |

## 五、内置约束

**X01** 只读审计，输出报告，不改代码（与 `uniapp-code-audit-skill` U01 一致）。

**X02** 每条记录写明影响平台、版本、路径行号、调用路径、依据、影响和证据状态；禁止输出修复方案。

**X03** 条件编译块必须**成对且可读**：`#ifdef` 与 `#endif` 配对，跨端分支不得只有单端实现而无兜底。

**X04** 平台专属 API 核查条件编译、调用可达性及已有降级路径，仅记录事实，不设计替代实现。

**X05** 单位统一 `rpx`；`px` 只在必须物理像素处使用（与上位规范 §4.2 一致）。

**X06** 按平台与容器责任检查安全区，不能仅因缺少 env() 判为问题。

**X07** 组件差异须有平台版本依据或运行证据；缺少证据标为待验证，列验证操作和预期结果。

**X08** 按 SKILL.md 的 P0–P3 和实际影响分级，待验证项不计入确认问题。

**X09** 报告中的"规范依据"引用必须带前缀（"R19"、"D11"）。

## 六、变更纪律

- 平台差异矩阵变更 → 同步 `SKILL.md` §1 与 `README.md`。
- 与 `uniapp-code-audit-skill` 的输出格式保持同步，两处同时改。
