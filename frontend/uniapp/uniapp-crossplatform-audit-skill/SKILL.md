# UniApp Cross-Platform Audit Skill

## 定位

本 skill 专门审计 uniapp 项目在三端（小程序 / H5 / App）运行时的兼容性问题，识别 H5 标签、浏览器 API、样式兼容性、条件编译缺失、平台配置缺陷等导致"一端正常、另一端崩溃"的隐患，**仅输出 `uniapp-crossplatform-audit-report.md` 报告，不修改、不修复、不重构项目代码**。

> 与 `uniapp-code-audit-skill` 的区别：本 skill 是**专项深度审计**，按项目目标与证据覆盖跨平台差异；`uniapp-code-audit-skill` 是**全维度体检**（10 维度），跨平台只是其中一维。

## When to Use

触发此 skill 时使用：

- "跨平台审计"
- "小程序 App 兼容"
- "多端兼容检查"
- "uniapp 三端表现差异"
- "H5 标签能不能跑小程序"
- "条件编译写得对不对"
- "App 端和小程序端有哪些坑"

## Workflow

```
Phase 1: 审计范围确认
   目标平台：微信小程序 / H5 / App / 其他小程序
   端数：2 端 / 3 端 / N 端
   重点维度：模板标签 / 样式兼容 / API 兼容 / 条件编译 / 平台配置

Phase 2: 多维度扫描
   按下列 6 个维度逐项扫描
   记录问题位置、风险等级、判定依据

Phase 3: 问题汇总
   按 P0/P1/P2/P3 风险等级归类
   列出"端间表现差异"专项问题

Phase 4: 输出报告
   生成 uniapp-crossplatform-audit-report.md
```

## 审计维度

### 语法与平台能力专项

- 模板：动态组件、插槽、表达式与事件，对照 Vue 版本及目标编译器，区分编译错误与运行错误。
- 脚本：分开核查语法降级和运行时对象，构建转换通过不代表 Promise、URL 等能力在目标环境存在。
- 样式：H5、App-vue、App-nvue 分开核对布局、选择器和属性兼容性，禁止假设 App 支持全部 Web CSS。
- 原生能力：plus.*、原生插件逐项核对系统、模块、权限及调用环境，追踪小程序/H5 分支是否误入。
- DOM：区分 H5、App 逻辑层、WebView/renderjs；小程序普通逻辑层不具备浏览器 DOM 环境。
- renderjs：对照官方支持范围，不把 App-vue 能力推广至 nvue 或小程序。
- 微信能力：区分小程序 wx.* 与网页 JS-SDK，核查基础库、授权及开放条件。
- 设备能力：摄像头、定位、蓝牙、文件逐 API 核对 Android/iOS、小程序、浏览器的版本、权限及安全上下文。
- 输出能力矩阵，列各平台支持条件、项目已有分支、证据、入口可达性与状态；不设计替代实现。

### 证据判定（覆盖后文旧扫描示例的直接定级规则）

1. 登记 uni-app/Vue 版本、微信基础库、H5 浏览器、App vue/nvue 模式及 Android/iOS 版本，缺项写待核实。
2. 关键词命中只建立候选。追踪入口、封装、条件编译及执行路径，结合对应版本官方兼容表或运行证据才能确认问题。
3. HTML 标签、background-image、calc()、CSS 变量、px/rpx 混用、缺少某条 env() 均不得单独作为不兼容结论。
4. 对齐同一业务的输入字段、请求参数、登录身份、成功/失败/取消结果和资源访问结果，平台专属交互按项目契约验收。
5. 键盘、安全区、滚动及原生层级需要运行证据。检查系统、页面、组件是否重复处理，不要求所有固定底栏上移，不从监听缺失推断遮挡。
6. 状态为已确认、待验证、不适用、未执行。每项包含平台版本、文件行号、调用路径、依据、影响、验证操作及预期结果。只统计已确认项为问题。
7. 只写审计报告。禁止修改业务源码、配置和依赖，禁止自动安装、构建、执行支付或上传。缺少运行前提记录未执行。
8. 禁止输出修复方案、替代实现、修复代码、补丁及自动修复命令。脚本结果逐条复核。

| 维度 | 主要内容 |
|------|----------|
| **模板标签** | `<div>` `<span>` `<p>` `<h1~h6>` `<img>` `<ul>` 等标签的目标编译转换与组件映射，命中只建立候选 |
| **样式兼容** | `background-image`、CSS 变量跨端差异、`px`/`rpx` 混用、`vw`/`vh` 适配问题 |
| **API 调用** | `fetch`/`window`/`document`/`localStorage`/`alert` 在小程序端不可用 |
| **条件编译** | `#ifdef MP-WEIXIN` `#ifdef APP-PLUS` `#ifdef H5` 使用是否完整 |
| **平台配置** | `manifest.json` 中 `mp-weixin`/`h5`/`app-plus` 各端差异化字段 |
| **端间表现差异** | 同一逻辑在三端的表现不一致（如键盘、滚动、安全区、支付回调） |


## 九项专项清单与取证要求

先读取业务契约、package.json、锁文件、类型与构建配置、manifest.json 和 pages.json。记录语言、Vue/uni-app、构建工具、状态库、UI 库和主要 SDK 的声明范围、锁定版本及可读取的安装版本，不安装依赖。区分声明依赖、实际导入和可达入口，DCloud 包版本不能直接等同上游 Vue 版本。缺项写待核实。

1. 模板与组件。核对转换、组件注册、属性事件和参数、目标编译器限制，分别记录编译与运行证据。
2. API 与依赖。追踪模块初始化及页面到 SDK 的路径，区分浏览器、Node 与平台对象。
3. 条件编译。检查 ifdef/ifndef/endif 配对及模板、脚本、CSS 注释形式，逐端推演裁剪后的变量和导入。
4. 样式与交互。区分 App-vue/nvue、PC/手机、触摸/鼠标、键盘、安全区、滚动与原生层级。单位和 CSS 命中不能直接定级。
5. 平台配置。核查路由、权限模块、网络策略、请求/上传/下载域名、H5 CORS 和签名；源码与控制台证据分开。
6. 业务结果。核对身份、Token、订单及成功、失败、取消、重复操作与恢复状态。真实上传、支付不自动执行。
7. 平台分支与微信登录。核查小程序凭证和后端认证、H5 网页授权的适用环境、App SDK/模块配置，按钮入口与各端实现一致。产品限定单端的能力可记录不适用，无须强制兜底。
8. 标签与 PC/手机适配。核对组件映射、DOM 使用层、宽屏布局、窄屏长内容、事件及最低环境；分别验收桌面与移动 H5。
9. 节点、Canvas 与文件链路。执行下方专项，不使用的能力记录不适用并说明依据。

### 节点与布局测量

区分 H5 DOM、小程序节点查询、App 逻辑层与视图层/renderjs、nvue。核查 createSelectorQuery 支持范围、渲染后时机、组件作用域、空结果和后续使用。布局信息、Canvas 节点不等同 HTMLElement。

### Canvas

区分传统 CanvasContext 与节点式 Canvas 2D，核对类型与版本、显示尺寸和像素尺寸、设备像素比、图片/字体就绪、H5 跨域与画布污染、绘制完成后的导出及资源预览保存。App 按渲染模式核查。清晰度、内存和实际导出需运行证据。

### 选图与拍照

核查隐私、相机/相册权限、取消、多选数量、格式与大小、压缩和方向。追踪文件对象、临时路径及生命周期，是否错误用作长期业务地址。授权拒绝后状态需验收。

### 上传

检查文件来源、项目实际 multipart/Base64 分支、字段、鉴权、HTTP 与业务状态、响应解析、最终 URL、进度、取消和重试。小程序查上传域名，H5 查 CORS 与凭证，App 查本地路径与网络策略。小程序并非必须使用 Base64。

### 下载、预览与保存相册

三项分别验收。检查 HTTPS/域名、签名 URL 过期与重定向、状态码、临时资源和持久化、相册授权拒绝与重试。H5 下载/长按保存不等同原生相册保存，App 按 Android/iOS 版本核查沙盒和权限。

### 报告验收

报告包含技术栈基线、九项覆盖矩阵、证据状态分组、已确认问题分级和未执行清单。每项写平台版本、入口和执行层、分支、文件行号、依据、影响、验证操作与预期结果。引用官方 API 表注明资料标题、地址与适用版本。六维用于归类，九项用于覆盖，不重复统计问题。扫描脚本仅供候选发现，不能替代版本依据和运行验证。

## 风险等级

| 等级 | 说明 |
|------|------|
| **P0 / Critical** | 某端完全无法运行或审核被拒 |
| **P1 / High** | 某端功能失效或行为异常 |
| **P2 / Medium** | 某端表现降级或样式不一致 |
| **P3 / Low** | 微小差异，建议优化 |

> 风险等级仅用于报告分类，**不代表修复指令**。

## 输出格式

生成 `uniapp-crossplatform-audit-report.md`，按风险等级分组列出问题，每条问题注明：

- 维度
- 风险等级
- 位置（文件 + 行号）
- 风险描述
- 判定依据
- 参考标准（`uniapp-app-generate-skill/references/cross-platform-compatibility.md` 等）

## 扫描方式

优先使用 Grep 等只读工具扫描。允许使用的命令示例：

```bash
# # H5 标签扫描
grep -rnE '<div|<span|<p|<h[1-6]|<img|<section|<article|<main' src/

# 小程序端不可用 API
grep -rnE 'fetch\(|window\.|document\.|localStorage|sessionStorage' src/

# 条件编译使用
grep -rnE '#ifdef MP-WEIXIN|#ifdef APP-PLUS|#ifdef H5' src/
```

### 端间表现差异专项（键盘 / 胶囊 / 安全区）

这三项是「一端正常、另一端被遮」的高发区，必须逐项扫，判据见 `uniapp/AGENTS.md` §9：

```bash
# 胶囊避让：自定义导航是否读了胶囊位置
grep -rn 'getMenuButtonBoundingClientRect' src/

# 键盘顶起：输入框是否声明 adjust-position
grep -rnE '<input|<textarea' src/ | grep -v 'adjust-position'

# 键盘顶起：固定底栏是否处理键盘高度
grep -rn 'onKeyboardHeightChange' src/

# 安全区候选：按平台和容器责任复核，不凭命中数量定级
grep -rn 'env(safe-area-inset' src/
```

以下脚本仅生成候选线索，不覆盖全部专项，结果需逐条追踪复核；先解析实际脚本路径再执行：

```bash
node ../uniapp-code-audit-skill/scripts/check-miniprogram.js <项目根目录>
```

| 维度 | 判定要点 |
|------|---------|
| 胶囊避让 | 核查公共导航或页面负责的胶囊避让，按实际布局和运行证据判断遮挡 |
| 键盘顶起 | 核查自动避让与手动位移是否叠加，按表单、固定输入栏、TabBar 场景验证 |
| 安全区 | 按系统、页面和公共容器责任核查顶部及底部补偿，确认内容可达及是否重复处理 |
| 登录四态 | loading / error / disabled / 重试 四态齐全（AGENTS.md §9.4） |

> 禁止在扫描过程中使用任何会修改项目的命令（如 `rm`、`mv`、`sed -i`、自动格式化等）。
