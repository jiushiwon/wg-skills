# 风险管理与成本控制

一句话：VibeCoding 中需要警惕的风险和成本问题。

## 1. AI 幻觉风险

### 问题

AI 可能生成：
- 不存在的 API
- 错误的代码逻辑
- 虚构的依赖版本
- 过时的最佳实践

### 应对

- [ ] 对 AI 生成的代码进行人工 review
- [ ] 关键逻辑必须有测试验证
- [ ] 不确定的 API 去官方文档确认
- [ ] 使用 `verification-before-completion` 类流程

## 2. 安全与隐私风险

### 问题

- 敏感信息被硬编码（API Key、密码）
- AI 处理用户隐私数据
- 不安全的依赖包
- 接口没有鉴权

### 应对

- [ ] API Key 放入环境变量
- [ ] 用户数据脱敏后再给 AI 分析
- [ ] 定期扫描依赖漏洞
- [ ] 关键接口必须鉴权
- [ ] 支付/资金逻辑人工 review

## 3. 代码质量风险

### 问题

- AI 生成大量重复代码
- 命名不规范
- 缺少错误处理
- 过度设计

### 应对

- [ ] 建立项目规范（可用 `frontend-style-harmonizer-skill`）
- [ ] 定期进行代码审查
- [ ] 复杂模块先出方案再写代码
- [ ] 删除死代码

## 4. 成本失控风险

### 问题

- AI API 调用量超出预期
- 多次重试导致费用翻倍
- 大上下文请求消耗大量 token
- 部署资源选型过高

### 应对

- [ ] 设置 API 调用预算上限
- [ ] 简单任务用本地模型或免费模型
- [ ] 压缩上下文，只传必要信息
- [ ] 缓存重复请求
- [ ] 监控每月 API 费用

## 5. 进度失控风险

### 问题

- 低估 AI 辅助开发的复杂度
- 反复修改导致时间超支
- 范围蔓延

### 应对

- [ ] 明确 MVP 范围
- [ ] 每个阶段设定 deadline
- [ ] 小步迭代，频繁验证
- [ ] 功能变更要经过评估

## 6. 依赖与供应商风险

### 问题

- AI 服务宕机
- 模型版本更新导致行为变化
- 免费额度用完
- 第三方 SDK 停止维护

### 应对

- [ ] 关键功能有降级方案
- [ ] 支持多模型切换
- [ ] 不要绑定单一供应商
- [ ] 重要依赖做版本锁定

## 7. 合规风险

### 问题

- 使用 AI 生成内容涉及版权
- 用户数据处理不符合法规
- 小程序/App 审核不通过

### 应对

- [ ] 了解目标平台的 AI 内容政策
- [ ] 用户数据最小化收集
- [ ] 隐私协议和用户协议齐全
- [ ] 小程序/App 提前了解审核规则

## 成本估算参考

| 项目规模 | AI API 月费用（参考） | 说明 |
|----------|----------------------|------|
| 个人原型 | $0-20 | 主要用免费额度 |
| 小型项目 | $20-100 | 中等调用量 |
| 中型产品 | $100-500 | 用户量增长 |
| 大型产品 | $500+ | 需要优化和缓存策略 |

> 以上仅为参考，实际费用取决于调用量、模型选择和上下文长度。

## 风险检查清单

项目在上线前建议检查：

- [ ] 没有硬编码敏感信息
- [ ] 核心流程有测试覆盖
- [ ] AI 生成代码已人工 review
- [ ] 已设置 API 预算和监控
- [ ] 有错误处理和降级方案
- [ ] 部署环境已配置日志和监控
- [ ] 合规文件齐全
