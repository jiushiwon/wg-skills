# 狐獴笔记接入设计

`wg-skills` 提供公开、可版本化的提示词模板。狐獴笔记用于个人整理和复用。计划中的 MCP 接入负责让智能体在用户授权后按分类找到并读取需要的提示词。

## 现有接口与边界

从 `humeng-uniapp-note/backend/app/routers/prompts.py` 和 `backend/app/utils/auth.py` 核对到：

- `GET /api/prompts` 支持分类和分页。
- `GET /api/prompts/mine` 使用 Bearer 登录态从服务端识别本人，当前查询范围为投稿记录（`submission`），支持分页和待审核选项，未提供个人分类筛选参数。
- `POST /api/prompts` 是需要登录的投稿入口，普通用户投稿进入审核。个人私有保存需要单独定义授权和可见范围。
- 首版模板可直接复制使用。以下 MCP 工具、授权流程及完整个人分类接口是设计目标。

## 首版只读接口

| 建议工具 | 输入 | 返回 |
|---|---|---|
| `list_prompt_categories` | 可选分页游标 | 当前授权范围内的分类及数量 |
| `search_prompts` | 分类、关键词、分页游标 | ID、标题、分类、版本和摘要 |
| `get_prompt` | ID、可选版本 | 正文、变量说明、版本、来源 |

调用顺序：用户在狐獴侧确认授权 → MCP 服务读取短期、可撤销的凭据 → 服务端按会话主体和授权分类查询 → 智能体按需加载一条正文。初期优先在服务端补齐个人分类与私有可见性，再实现 MCP 适配层。

`openid` 可作为服务端绑定账号的标识。访问凭据应来自用户确认后的授权流程；单独提交 `openid`、更换请求里的用户 ID 或猜测记录 ID 都不能读取个人内容。远程 HTTP MCP 设计遵循适用的授权规范，区分 MCP 访问令牌与狐獴服务自己的凭据，按服务端配置校验受众、期限和权限。凭据通过授权通道传输，提示词和公开示例里只放虚构数据。[MCP 授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)

## 模板与收藏如何对齐

保存公开模板时记录 `template_id`、版本和来源。个人副本允许改名、分类和编辑，拉取公开新版本时先展示差异，由用户决定是否更新。搜索只返回摘要，读取正文由当前任务触发。取回的内容先作为数据处理，执行与工具权限仍由当前会话和用户授权决定。

## 接入验收

- 未登录、过期及撤销后无法列出私有分类或读取正文。
- 用户 A 提供用户 B 的 `openid` 或记录 ID 时仍无法跨账户读取。
- 分类与分页只返回本次授权范围，正文可定位到具体版本。
- 本地、公开、投稿及私有内容按各自的可见性规则返回。查询不会触发发布或覆盖个人副本。
