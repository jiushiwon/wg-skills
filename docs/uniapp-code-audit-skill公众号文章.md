# 一天一个SKILL—— uniapp代码体检神器升级！10大维度全面审计，从安全到 App 端专享、从死代码到三端差异，一次查清

大家好，我是【考拉搞AI】，一个专注于 `VibeCoding` 分享 & `AI 工程化` 的博主。

之前给大家带来了一系列 `uniapp` 相关的 `SKILL`：开发规范、主题系统、UI复刻、请求封装……小伙伴们反响都很热烈🔥，看来大家手头的小程序项目是真不少。

不过有个问题一直困扰大家：**规范有了、代码写了，可写完之后到底靠不靠谱？能不能上架？有没有坑？** 全凭感觉可不行。

今天给大家带来一个**硬核体检神器**——`uniapp-code-audit-skill`，专门给 uniapp 项目做全面体检：安全、性能、代码质量、架构、UI/主题、跨平台、小程序专项、**App 端专项（Android/iOS）**、**冗余与死代码**、API 契约，**从 8 大维度升级至 10 大维度**，而且只出报告、不动代码，安全放心。

---

## 一、痛点

做过 uniapp 小程序的同学都懂，尤其是用 `AI` 写代码的：

| 痛点 | 后果 |
|------|------|
| 敏感信息写死 | API Key/密钥裸奔在代码里，上架即泄露 |
| 包体积超标 | 主包超 2MB，审核直接被拒 |
| 硬编码满天飞 | 颜色尺寸各不同，UI 东一块西一块 |
| 接口调用混乱 | 有的 uni.request，有的 axios，401/403 没人管 |
| H5 正常小程序/App 表现烂 | 跨端兼容性黑洞，测完 H5 才发现另外两端一塌糊涂 |
| 冗余代码堆积 | 废弃页面/组件/资源无人清理，包体积越滚越大 |
| 安卓/iOS 平台差异 | 返回键、权限、状态栏、字体渲染两端不一致 |
| 代码审查 | 凭感觉，看心情，没有标准 |

**尤其是上架小程序**，审核被拒是常态，问题往往出在你根本想不到的地方：

- 主包大小超限 → 审核被拒
- 敏感信息泄露 → 合规不过
- 隐私政策缺失 → 审核被拒
- 危险 API（eval/new Function）→ 审核被拒
- 长列表无限加载 → 页面卡死，用户流失
- App 端未处理 Android 返回键 → 用户按返回键直接退出
- iOS 权限描述缺失 → App Store 审核被拒
- 废弃页面/组件散落 → 包体积膨胀，维护一塌糊涂

等到上线前一天才发现这些问题，那才叫**欲哭无泪**。这时候，你就需要一个**审计 skill** 来给项目做全面体检！

## 二、功能介绍

一句话总结：**输入指令 → 10 大维度全面扫描 → 输出分级审计报告，帮你把项目问题一次查清。**

### 1. 10 大审计维度

覆盖一个 uniapp 项目的方方面面，**从 8 维升级到 10 维**：

| 维度 | 查什么 |
|------|--------|
| 安全合规 | 敏感信息、域名配置、隐私合规、调试代码、依赖漏洞 |
| 性能 | 包体积、图片优化、网络请求、长列表、setData、缓存 |
| 代码质量 | TypeScript 安全、硬编码、重复代码、错误处理、组件规范 |
| 架构与规范 | 目录结构、红线规则、配置文件、状态管理、构建/lint |
| UI/主题一致性 | 颜色、字号、间距、圆角阴影、组件复用、交互反馈 |
| 跨平台兼容 | H5 标签、CSS 兼容性、浏览器 API、条件编译、安全区、**三端表现差异对比** |
| 小程序专项 | setData、页面栈、分包体积、隐私合规、合法域名、版本更新 |
| **🆕 App 端专项** | **Android/iOS 差异、plus 原生能力、nvue、App 包体积、热更新、推送、App 端安全** |
| **🆕 冗余与死代码** | **未引用页面/组件/静态资源、死代码、注释旧逻辑、冗余依赖** |
| API 契约 | 请求层封装、响应结构、Token 注入、401/403、防抖去重、Mock |

### 2. P0-P3 风险分级

审计结果不糊成一团，而是按风险等级归类，**先看最要命的**：

| 等级 | 说明 |
|------|------|
| **P0 / Critical** | 违反强制红线或上线合规要求，可能导致审核被拒、安全漏洞或严重性能问题 |
| **P1 / High** | 高风险偏差，影响功能、性能或稳定性 |
| **P2 / Medium** | 中风险偏差，影响可维护性或规范符合性 |
| **P3 / Low** | 优化建议，偏离程度较轻 |

每个问题都标注：**位置、风险描述、判定依据、参考标准**，有理有据，不冤枉不放过。

### 3. 只体检，不「开药方」

这个 skill 最大的特点：**只输出 `uniapp-audit-report.md` 报告，不修改、不修复、不重构项目代码。**

为什么？因为体检和治病是两回事。先让 AI 把问题查清楚，再由对应的规范化 skill 去落地修改，各司其职，才不会乱。

### 4. 增量审计，只查最新改动

只改了几行代码，不想全量扫描？

```bash
> 只审计我还没提交的改动有没有问题
```

skill 只扫描 git 未提交的 diff，**快速排查新增问题**，省时省力。

### 5. 平台过滤，不误报

小程序专属检查项（包体积、合法域名、审核合规、分包）**仅在目标平台包含小程序时执行**；App 端专项检查项（Android/iOS 差异、原生能力、热更新）**仅在目标平台包含 App 时执行**。做 H5 的项目不会被小程序规则或 App 端规则误伤。

### 6. 抽样审计，大项目不焦虑

项目太大、问题太多？可以指定模块/文件范围做抽样审计，**避免全量噪音**。

## 三、使用方式

### 老地址：`https://github.com/jiushiwon/wg-skills/tree/main/uniapp-code-audit-skill`

### 触发命令

```markdown
/uniapp-code-audit-skill 帮我审计一下这个 uniapp 项目
```

或描述：
- "uniapp 安全审计"
- "uniapp 性能审计"
- "检查这个项目是否符合 uniapp 开发规范"
- "uniapp App 端审计"
- "安卓/苹果端兼容性审计"
- "帮我看看这个 uniapp 项目有什么问题"
- "审计这个项目有没有冗余代码或没用的页面组件"
- "小程序能过审吗"
- "只审计我还没提交的改动"

### 实战示例

```bash
# 全面审计
> 帮我审计一下这个 uniapp 项目的代码质量

# 重点查安全
> 看看这个项目有没有安全漏洞

# 重点查性能
> 帮我看看有没有性能问题

# 单维度审计
> 检查一下这个项目的 UI/主题是否一致
> 帮我看看接口封装有没有问题
```

### 审计流程

```
Phase 1: 审计范围确认
  → 全量 or 指定模块/页面
  → 目标平台：微信小程序 / H5 / App
  → 重点维度：安全 / 性能 / 代码质量 / 架构 / UI/主题 / 跨平台 / 小程序 / App 端 / 冗余与死代码 / API 契约
  → 可选：增量审计 / 抽样审计

Phase 2: 多维度扫描
  → 10 大维度逐项扫描
  → 记录位置、风险等级、判定依据

Phase 3: 问题汇总
  → 按 P0/P1/P2/P3 归类统计
  → 评估维度健康度

Phase 4: 输出报告
  → 生成 uniapp-audit-report.md
```

## 四、配合使用

```

   │                      │                      │                 │
```

## 五、效果对比

| 场景 | 没有审计 | 有审计 |
|------|----------|--------|
| 上架审核 | 被拒了才知道问题 | 上线前就查出合规风险（小程序 + App 双端） |
| 安全 | 密钥泄露了才后悔 | P0 级漏洞提前暴露 |
| 性能 | 线上卡顿才知道 | 包体积/setData/图片资源 提前优化 |
| 跨平台 | H5 没问题，小程序/App 卡成翔 | 三端差异检查项，避免一端独好 |
| App 端 | Android 返回键、iOS 权限缺失才发现 | App 端专项审计，审核/体验一把抓 |
| 冗余清理 | 项目越滚越大 | 定位未引用页面/组件/死代码，按图索骥 |
| 代码审查 | 凭感觉，没标准 | 对照 10 大维度，有理有据 |
| Vue2 老项目 | 不敢动，怕踩坑 | 快速摸底，明确升级路径 |
