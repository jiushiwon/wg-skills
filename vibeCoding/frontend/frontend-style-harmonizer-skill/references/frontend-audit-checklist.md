# 前端一致性审计清单

## 取证和输出规则

每项输出使用列表：发现什么 → 哪些文件和行号 → 对照哪个公共实现或规范 → 影响什么 → 建议怎么改 → 如何验证。统计必须写明是页面数、文件数还是代码出现次数；无证据不补数字，不将风险写成已发生故障。区分已证实、待运行验证、不适用、未检查。模拟示例单独标记，不计入审计统计。只读报告中的改前/改后是建议，不代表已经修改。

## 六类审计

1. **公共组件**：先找项目已有 Button、Search、Input、Checkbox 等公共实现，再查各页面是否调用。例：A 页面用 AppButton，B 页面同样的保存操作却手写 button。对照尺寸、加载、禁用、错误反馈及交互。特殊业务控件记录例外理由，不按标签一刀切替换。
2. **主题**：先读项目主题规范，对照字体大小、主题色、圆角、间距等 Token 是否有唯一来源、是否被组件和页面实际使用、主题切换是否生效。按栈参考 [Vue 主题](../../vue/vue-theme-skill/SKILL.md) 或 [UniApp 主题](../../uniapp/uniapp-theme-skill/SKILL.md)。引用 Token 不等于已统一；有意使用的层级、语义色、品牌例外不强行合并。
3. **页面空间**：分别记录页面四周留白、区域内部 padding、区域之间 gap/margin、顶部距离、页面宽度和 max-width、固定区域补偿；小程序还查胶囊按钮边界、自定义导航高度。追踪页面容器、卡片、业务区谁负责哪层空间，计算叠加关系。先读项目规范；没有规范则提出待确认的责任表和档位，不自行宣布某个数值是全局标准。用规范强制审核责任一致，而非强制所有页面同值。不能只凭截图相似或 margin 数值不同判错。
4. **兼容性**：按目标端查键盘顶起、页面位移与组件自动顶起是否重复，底部安全区是否统一处理、是否重复补偿、滚动区是否预留底栏高度；无输入页不强查键盘。静态检查仅证明代码路径，真机需覆盖弹起、收起、最后一项可见、底栏及横竖屏。专项参考 [UniApp 跨平台审计](../../uniapp/uniapp-crossplatform-audit-skill/SKILL.md)。
5. **图标**：对照同一动作跨页面使用的资产、图标库、大小、颜色、点击区及禁用/危险状态。例：A 页编辑用铅笔，B 页编辑换成其他图标或缺图标。先列实际覆盖页面，不凭一个样本推断全局；有文字替代且语义明确的场景记录设计依据。
6. **接口请求**：只查前端。是否复用统一请求实例和环境地址、Token、超时、拦截器；同一接口的入参字段、类型、分页和出参解包是否一致；成功提示是否重复，失败是否统一反馈，loading 是否收尾，空数据、登录失效及重复提交如何处理。结合 [公共请求规范](../../frontend-request-skill/SKILL.md)，UniApp 再参考 [UniApp 请求](../../uniapp/uniapp-request-skill/SKILL.md)。业务特殊接口可保留例外，但需说明。请求参数、返回结构和调用时机默认仅报告，不随样式 --apply 修改。

## 分批审计与边界

每次声明实际覆盖的端、页面、状态和证据来源。默认覆盖上述六类，不适用项写原因；未取证的内容必须写未检查。不得因 all 参数宣称所有前端质量已经通过。

收尾必须列出未覆盖或需专项验证项：iPad/iPhone/PC 不同宽度的自适应；onLoad/onShow/挂载/返回页时的数据请求、刷新、缓存、重复调用、竞态及渲染状态；文字溢出、省略、换行和长内容；实际真机安全区与键盘验收。用户要求时纳入专项审计，否则明确是下一轮工作。后端鉴权实现、业务校验、数据库、性能和安全不在本技能前端审计结论内。
