# 五端设计基线与单位映射

## 一、基线不是硬编码

下表用于设计稿、组件尺寸和交付标注。状态栏、底部手势、微信胶囊、软键盘和窗口尺寸必须由运行时获取，不能把表中任何高度复制进业务页面。

| 平台 | 设计/布局单位 | 文字单位 | 常用设计宽度 | 最小触控目标 | 必须额外关注 |
| --- | --- | --- | --- | --- | --- |
| iOS | pt | pt | 393pt 作为常规参考 | 44 × 44pt | Safe Area、动态岛、Home Indicator、动态字体 |
| Android | dp | sp | 360dp 作为常规参考 | 48 × 48dp | 屏幕密度、字体缩放、分屏/折叠态 |
| 微信小程序 | rpx | rpx | 750rpx 设计稿 | 88 × 88rpx | 胶囊、原生/自绘导航、底部安全区 |
| 移动 H5 | CSS px / rem / vw | CSS px / rem | 375 CSS px 作为常规参考 | 44 × 44 CSS px | viewport、浏览器工具栏、`env()`、键盘 |
| 鸿蒙 ArkUI | vp | fp | 以窗口可用宽度为基线 | 以当前组件/无障碍规范复核 | 多窗口、折叠态、避让区、字体缩放 |

## 二、稳定的跨端空间意图

| 设计意图 | 建议基线 | 交付时必须说明 |
| --- | --- | --- |
| 页面外侧 gutter | 16–20 个逻辑单位起步 | 由 PageContainer 还是页面私有样式负责 |
| 卡片内部 padding | 12–24 个逻辑单位 | 与页面 gutter 不可混为同一个变量 |
| 正文 | iOS 约 15–17pt；Android/H5 常规 14–16 逻辑单位 | 是否跟随系统字号，最小可读字号 |
| 图标 | 视觉尺寸可小 | 点击命中区仍须达到该端最小触控目标 |
| 固定底栏 | 组件自身 + 安全区 | 内容区预留高度与键盘弹起策略 |

## 三、iPhone 常用设计参考与安全区

| 参考机型 | 逻辑尺寸 | 倍率 | 重点验收 |
| --- | --- | --- | --- |
| iPhone SE（第 3 代） | 375 × 667pt | @2x | 小屏、键盘、长文案、底部按钮 |
| iPhone 13 / 14 | 390 × 844pt | @3x | 常规刘海/手势屏 |
| iPhone 15 / 15 Pro | 393 × 852pt | @3x | 常规设计基线、灵动岛区域 |
| iPhone 15 Plus | 428 × 926pt | @3x | 大屏纵向空间 |
| iPhone 15 Pro Max | 430 × 932pt | @3x | 长列表、固定底栏、信息密度 |

- 可选择 393 × 852pt 作为常规设计参考，但至少同时验证 375 宽度的小屏与 430 宽度的大屏。
- 原生交互控件的一般最小点击命中区为 44 × 44pt；视觉尺寸可小于命中区。
- 顶部状态、底部 Home Indicator、导航栏和 TabBar 共同决定可用区域。具体 inset 必须从运行时 Safe Area 获取，禁止用机型表推算固定高度。

## 四、Android 密度换算参考

| 密度等级 | 倍率 | 1dp 对应物理 px | 常见物理分辨率参考 |
| --- | --- | --- | --- |
| mdpi | 1x | 1px | 320 × 480 |
| hdpi | 1.5x | 1.5px | 480 × 800 |
| xhdpi | 2x | 2px | 720 × 1280 |
| xxhdpi | 3x | 3px | 1080 × 1920 |
| xxxhdpi | 4x | 4px | 1440 × 2560 |

- 布局/控件用 `dp`，文字用能响应系统字号的 `sp`；不可把物理 px 直接当作设计单位。
- 常用设计基线可选 360dp 宽度；Android 还应验证字体放大、分屏和折叠态。
- 交互控件以 48 × 48dp 作为常规最小触控目标。

## 五、微信小程序：胶囊与自定义导航

小程序的 `rpx` 只解决宽度比例，不解决右上角胶囊、自定义导航和状态栏。

| 设计/实现项 | 唯一取值口径 | 禁止做法 |
| --- | --- | --- |
| 状态栏 | `uni.getSystemInfoSync().statusBarHeight` | 写死 44px / 88rpx |
| 胶囊矩形 | `uni.getMenuButtonBoundingClientRect()` | 假设所有机型胶囊位置相同 |
| 导航高度 | 状态栏 + 胶囊带 + 标题行，由项目导航容器计算 | 在页面中各自写导航高度 |
| 右侧内容 | 右边界不越过胶囊左边界 | 标题、菜单、按钮压在胶囊带内 |

交付要求：胶囊带内只放返回等必要操作；标题独立成行；页面首个内容元素在导航总高之后。若项目使用原生导航，则不要再叠一套自绘安全区。

## 六、不要直接转换的项目

- `1pt = 1dp = 1px = 2rpx = 1vp` 只能作为局部设计心智模型，不能写成跨端实现公式。
- 设计稿宽度不是设备白名单；要额外验证最小、常规、大屏/横屏与折叠态。
- `safe-area-inset-*` 对 H5 有意义，但不是微信小程序顶部胶囊的替代；小程序顶部应取状态栏和胶囊运行时信息。

## 七、移动 H5 的动态单位与计算

| 写法 | 适合什么 | 不该承担什么 |
| --- | --- | --- |
| `px` | 边框、图标视觉尺寸、精确的设计基线 | 不能单独解决大屏与字体缩放 |
| `rem` | 字号、可跟随根字号的间距体系 | 根字号策略不统一时会放大漂移 |
| `em` | 与当前组件字体大小成比例的局部间距 | 不适合跨组件的全局空间 Token |
| `vw` | 随视口宽度伸缩的 Hero、流式尺寸 | 不可用于正文最小字号或关键点击区 |
| `dvh` | 需要随移动浏览器动态工具栏变化的全屏区域 | 不能替代底部安全区和键盘验证 |
| `svh` | 需要保证“小可视高度”仍不溢出的首屏 | 不适合必须铺满当前可视区的沉浸内容 |
| `lvh` | 允许以最大可视高度布局的沉浸背景 | 不能假设工具栏始终收起 |
| `calc()` | 合并 Token、固定栏与 `env()` 安全区 | 不应用无来源的魔法数堆公式 |
| `clamp()` | 在最小、流式和最大值之间限制字号/间距 | 不替代组件尺寸阶梯和真机验收 |

推荐 H5 模式：页面用 `min-height: 100dvh`；正文/标题用 `clamp()` 控制极端宽度；固定栏与内容区用 `calc(Token + env())` 成对处理。示例：

```css
.page { min-height: 100dvh; }
.page-title { font-size: clamp(22px, 5vw, 30px); }
.page-footer { padding-bottom: calc(var(--space-4) + env(safe-area-inset-bottom, 0px)); }
.page-content { padding-bottom: calc(var(--footer-height) + env(safe-area-inset-bottom, 0px)); }
```

## 八、官方依据

- Apple HIG：按钮命中区一般至少 44 × 44pt；Safe Area 用于避开硬件与系统 UI。
- Material Design：Android 交互控件以 48dp 触控目标作为常规基线，文字使用可缩放 `sp`。
- MDN：CSS `env(safe-area-inset-*)` 是用户代理定义的环境变量，应提供 fallback。
- 微信小程序：`rpx` 按屏幕宽度比例换算；状态栏与胶囊位置必须使用运行时 API。

> 具体数字、端侧 API 和机型适配策略会随平台更新；项目交付前必须复核对应官方文档。
