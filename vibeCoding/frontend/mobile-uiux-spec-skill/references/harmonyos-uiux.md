# 鸿蒙 UI/UX 交付 Variant

## 一、为什么单列鸿蒙

鸿蒙不是“把 Android dp 换个名字”。当目标为 ArkUI/HarmonyOS 时，设计需要同时面对手机、平板、折叠态和多窗口；单一 360 宽度设计稿无法覆盖全部情况。

## 二、单位与布局

| 项目 | 基线 | 说明 |
| --- | --- | --- |
| 布局尺寸 | `vp` | 随屏幕密度变化的视觉像素，页面尺寸和间距优先使用 |
| 字体 | `fp` | 应尊重用户字体缩放；不要将可读性依赖固定高度 |
| 宽度策略 | 窗口可用宽度 | 根据窗口而非设备型号决定单栏/双栏/分栏 |
| 安全区 | 端侧避让能力 | 沉浸式、挖孔、导航条和键盘由运行时获取，不写死 |

## 三、必须补的 Variant

1. **窄窗/折叠态**：单栏、固定底栏、表单和键盘可达性。
2. **展开态/平板**：内容最大宽度、双栏信息优先级、空白区不能只放大手机布局。
3. **窗口变化**：旋转、分屏和窗口缩放时，不依赖初始宽高计算一次后永久使用。
4. **避让区**：顶部状态、底部导航、软键盘、挖孔/圆角区域与内容层分开处理。

## 四、交付说明模板

```markdown
### 鸿蒙 Variant

- 窄窗：单栏，页面 gutter 由 PageContainer 统一提供。
- 宽窗：主内容设置最大可读宽度；辅助信息进入右侧栏或折叠面板。
- 单位：布局用 vp，文字用 fp；不得把 Android dp/sp 直接复制到 ArkUI。
- 避让：沉浸式页面调用项目选定的端侧避让方案；未接入前标记待验证。
- 验收：窄窗、展开态、字体放大、键盘弹起、窗口尺寸变化。
```

## 五、边界

本文不绑定某个 HarmonyOS API 版本。实际项目调用安全区、窗口和折叠状态 API 前，必须根据当前 SDK 与官方文档核实；本 Skill 负责设计责任与验收项，不伪造端侧实现。
