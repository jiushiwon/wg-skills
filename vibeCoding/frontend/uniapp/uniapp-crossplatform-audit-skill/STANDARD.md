# uniapp-crossplatform-audit-skill 个体规范

> 上位规范：[uniapp/AGENTS.md](../AGENTS.md)
> 本文件只写本模块特有约束；与上位规范重复的内容不再赘述。

## 一、模块定位

**第 2 层：专项层（跨端兼容审计）。**

本模块审计 uni-app 项目在各端（微信小程序 / 支付宝 / 抖音 / H5 / App / 鸿蒙）上的**兼容性问题**：平台专属 API、条件编译、样式差异、组件差异、性能差异。

> **边界**：与 `uniapp-code-audit-skill` 的分工是"通用规范"与"跨端差异"。本模块不看通用红线，只看跨端。

## 二、依赖

| 依赖 | 方向 | 用途 |
|------|------|------|
| `uniapp-standard-skill` | 依赖（前置规范） | R19 鸿蒙降级、目录与命名 |
| `uniapp-code-audit-skill` | 平行 | 输出形式对齐（报告结构、风险分级） |

## 三、目录约定

```
uniapp-crossplatform-audit-skill/
├── SKILL.md
├── README.md
└── STANDARD.md                       # 本文件
```

- 本模块无 `references/`：内容体量小，全部收在 `SKILL.md`。
- 报告产物：与代码审计同名的 `uniapp-audit-report.md`（跨端章节独立成节），或在项目内单独输出 `uniapp-crossplatform-audit.md`。

## 四、内容清单

| 章节 | 内容 |
|------|------|
| §1 平台差异矩阵 | 各端能力差异对照 |
| §2 条件编译 | `#ifdef` / `#ifndef` 用法与覆盖完整性 |
| §3 API 兼容 | 平台专属 API 的替代方案 |
| §4 样式兼容 | 选择器、伪类、单位、`env()` 安全区 |
| §5 组件兼容 | 内置组件在各端的支持差异 |
| §6 性能差异 | 包体积、渲染、API 频次限制 |
| §7 降级策略 | 鸿蒙 / 低端机降级 |

## 五、内置约束

**X01** 只读审计，输出报告，不改代码（与 `uniapp-code-audit-skill` U01 一致）。

**X02** 每条问题必须写明：**影响平台**（可多选）、路径行号、平台差异事实、修复方案。

**X03** 条件编译块必须**成对且可读**：`#ifdef` 与 `#endif` 配对，跨端分支不得只有单端实现而无兜底。

**X04** 平台专属 API 必须标注替代方案或降级路径，禁止只写"该 API 在 XX 端不支持"就结束。

**X05** 单位统一 `rpx`；`px` 只在必须物理像素处使用（与上位规范 §4.2 一致）。

**X06** 安全区必须用 `env(safe-area-inset-*)`，不得写死数值。

**X07** 涉及 `scroll-view` / `swiper` / `video` / `map` 等组件的差异，必须给出实际平台结论，不写"可能存在差异"。

**X08** 风险分级与 `uniapp-code-audit-skill` 的 P0–P3 保持一致，跨端问题最高可判 P1。

**X09** 报告中的"规范依据"引用必须带前缀（"R19"、"D11"）。

## 六、变更纪律

- 平台差异矩阵变更 → 同步 `SKILL.md` §1 与 `README.md`。
- 与 `uniapp-code-audit-skill` 的输出格式保持同步，两处同时改。
