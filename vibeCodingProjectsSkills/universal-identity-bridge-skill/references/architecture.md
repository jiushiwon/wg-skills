# 统一身份接入架构

## 核心边界

统一的是身份锚点与受控授权，不是把所有项目的用户数据塞进同一张表。

```text
身份中枢：宿主账户、登录凭证、角色权限、应用密钥、绑定关系
    │
    ├── 项目 A：头像、内容、订单
    ├── 项目 B：只保存 globalUserId 与自身业务数据
    └── 项目 C：生活习惯等敏感资料，独立表、独立权限、独立删除策略
```

当前身份锚点是宿主 `sys_user_id`。`globalUserId`/UUIDv7 是下一阶段的跨项目公开标识，尚未实施；任何业务项目不得抢先假定该字段存在。

## 已实现身份链路

1. 用户以宿主账户登录。
2. 业务应用通过 `apiKey + apiSecret` 对开放接口做 HMAC 签名。
3. 绑定码以“应用发起确认”或“宿主发起扫码认领”方式一次性消费。
4. 中枢保存宿主用户与应用用户的绑定关系。

## 数据归属规则

| 数据 | 归属 |
|---|---|
| 密码、登录状态、角色、应用密钥 | 身份中枢 |
| 应用侧用户编号与绑定关系 | 身份中枢 |
| 业务资料、订单、内容、敏感生活数据 | 对应业务项目 |
| 全局公共资料 | 后续单独设计，需明确 Scope 与用户授权 |
