# Humanizer: 去除AI写作模式

让AI生成的文字读起来像人写的，不改变原意。基于维基百科"AI写作迹象"项目（WikiProject AI Cleanup）维护的35个模式。

## 核心原则

1. **保留所有事实**。可以缩短冗余部分、扩展有用内容、合并或拆分段落，但信息不能丢。
2. **不编造细节**。不添加原文没有的事实、人名、数字、日期、引文或引用。如果句子缺少必要细节，要么问用户，要么用更简单的句子。
3. **匹配作者风格**。根据文本类型使用合适的语气（正式/随意/技术性）。只有在文本和作者需要时才加入个性。
4. **允许不完美**。人写的文章会有犹豫、自我修正、不均匀的节奏——这些是人的痕迹，不要删掉。

## 使用方式

直接调用：

```
/humanizer
[粘贴文本]
```

或用自然语言：

```
帮我去除这段文字的AI味道：[粘贴文本]
```

重写文件：

```
去掉 docs/launch-post.md 的AI味道
```

### 匹配你的风格

如果想让重写更像你自己的风格，附上样本：

```
/humanizer

以下是我写的样本：
[粘贴2-3段你自己的文字]

帮我改掉这段的AI味道：
[粘贴AI生成的文本]
```

## 35个AI写作模式

### 内容模式

| # | 模式 | 示例（改前） | 示例（改后） |
|---|------|-------------|-------------|
| 1 | **夸大重要性** | "标志着区域统计学演进的关键时刻" | "1989年成立，是西班牙行政权力下放的一部分" |
| 2 | **名人背书** | "被纽约时报、BBC、金融时报引用" | "被纽约时报和BBC引用" |
| 3 | **浅层-ing分析** | "象征着...反映...展示..." | 只保留原文支持的内容 |
| 4 | **销售话术** | "坐落在令人叹为观止的地区" | "是埃塞俄比亚贡德尔地区的一个城镇" |
| 5 | **模糊来源** | "专家认为它起着关键作用" | 要么给出具体来源，要么删除该说法 |
| 6 | **公式化挑战与展望** | "尽管面临挑战...持续蓬勃发展" | 保留事实，删除套话 |

### 语言和语法模式

| # | 模式 | 示例（改前） | 示例（改后） |
|---|------|-------------|-------------|
| 7 | **AI高频词** | "实际上...此外...关键...深入...展示" | "也...需要...仍然常见" |
| 8 | **回避is/are** | "作为...拥有...提供" | "是...有" |
| 9 | **Not X but Y** | "不仅仅是X，更是Y" | 直接陈述观点 |
| 10 | **强制三连** | "创新、灵感和洞察" | 按实际需要的数量 |
| 11 | **同义词替换/重复开头** | "主角...主人公...英雄" | 用同一个名称，或合并重复句子 |
| 12 | **虚假范围** | "从大爆炸到暗物质" | 直接列出主题 |
| 13 | **被动语态** | "无需配置文件" | "你不需要配置文件" |

### 风格模式

| # | 模式 | 示例（改前） | 示例（改后） |
|---|------|-------------|-------------|
| 14 | **破折号滥用** | "机构——不是人民——" | "机构，不是人民，" |
| 15 | **加粗过多** | "**OKRs**、**KPIs**、**BMC**" | "OKRs、KPIs、BMC" |
| 16 | **列表+粗体小标题** | "**性能：** 性能提升..." | "更新改善了界面，加快了加载速度..." |
| 17 | **标题大写** | "战略谈判与合作伙伴关系" | "战略谈判与合作关系" |
| 18 | **Emoji** | "🚀 启动阶段：💡 关键洞察：" | 删除emoji |
| 19 | **花引号** | `他说"项目在正轨上"` | `他说"项目在正轨上"` |
| 26 | **过多连字符词** | "跨职能、数据驱动、面向客户" | 只保留语法需要的连字符 |
| 27 | **假装揭示深层真相** | "本质上，真正重要的是..." | 直接陈述观点 |
| 28 | **预告下一点** | "让我们深入了解" | 直接开始内容 |
| 29 | **标题重复** | "## 性能" + "速度很重要。" | 让标题自己说话 |
| 30 | **描述旧版本** | "此函数用于替代之前的..." | 描述它现在做什么 |
| 31 | **强制金句** | "它没有偏好。没有先验。没有怀旧。" | 用自然长度的句子和具体说法 |
| 32 | **公式化格言** | "对称是信任的语言" | 陈述具体观点 |
| 33 | **假装坦诚** | "老实说？这取决于..." | 直接回答 |
| 34 | **回答没人问的反对** | "这不是主要关于..." | 删除无依据的辩护 |
| 35 | **否定虚假选项** | "一个诱人的选择是...但是" | 删除假选项，保留真正选择 |

## 聊天模式

### 20. 聊天残留文本

**常见词：** 希望这对你有帮助！, 当然！, 你说得对！, 需要我...吗？

**改前：**
> 以下是法国大革命的概述。希望这对你有帮助！需要我展开某个部分吗？

**改后：**
> 法国大革命始于1789年，财政危机和粮食短缺导致了广泛的动荡。

### 21. 知识截止声明

**常见词：** 截至..., 根据我最后的训练数据, 虽然具体细节有限..., 基于可用信息

**改前：**
> 虽然关于公司创立的具体细节在现有资料中没有广泛记录，但它似乎成立于1990年代。

**改后：**
> 公司的创立日期在现有资料中没有记录。（或删除该句）

### 22. 过度赞同

**改前：**
> 好问题！你说得对，这确实是一个复杂的话题。

**改后：**
> 你提到的经济因素在这里很关键。

## 填充和修饰

### 23. 填充短语

- "为了实现这个目标" → "为此"
- "由于下雨这个事实" → "因为下雨"
- "在此时此刻" → "现在"
- "如果你需要帮助的话" → "如果你需要帮助"
- "系统具有处理的能力" → "系统可以处理"
- "值得注意的是数据显示" → "数据显示"

### 24. 过多修饰语

**常见词：** 说句公道话, 也有可能, 可能潜在地, 在某些情况下

**改前：**
> 可能可以说该政策可能对结果有一些影响。

**改后：**
> 该政策可能影响结果。

### 25. 泛泛正面结尾

**改前：**
> 公司的未来看起来很光明。激动人心的时刻即将到来。

**改后：**
> （删除段落，以最后一个具体事实结尾）

## 检查误报

### 不要标记的情况

- **完美语法和一致风格。** 很多作者是专业人士或经过编辑。
- **混合正式和随意风格。** 可能反映作者的领域、年龄或个人习惯。
- **正式或学术词汇。** 第7条列出的是AI过度使用的特定词，不是所有正式词。
- **花引号单独出现。** macOS、Word、Google Docs默认使用花引号。
- **破折号单独出现。** 很多编辑和记者常用破折号。
- **一个短句表示强调。** 只有连续多个短片段才值得标记。
- **2022年11月30日之前的编辑。** ChatGPT公开发布之前的内容几乎不可能是AI写的。

### 保留的人味细节

- **具体、不寻常的细节。** 保留真实地址、奇怪的引用。
- **矛盾情感和未解决的张力。** "我觉得这大部分是好的，但就是让我困扰，我说不清为什么。"
- **时代特定的引用。** 梗、俚语、内部笑话。
- **刻意的第一人称选择。**
- **句子长度变化。** 真正的写作长短交替，AI倾向于均匀的中等长度。
- **真实的自我修正。** "（我一直想在这里说'几乎'，但确实就是确定的。）"

## 重写流程

1. **读原文，标记AI模式。**
2. **写初稿。** 默读一遍。检查节奏、细节、简单动词（is/has）、合适的正式程度。
3. **问自己两个问题：**
   - "还有什么听起来像AI写的？"
   - "重写时有没有添加或删除任何事实、人名、数字、日期、引文？"
4. **写最终版本。** 自然地陈述每个观点，而不是逐个修补标记的短语。如果句子仍然别扭，围绕其主要观点重写段落。

## 与 ai-speech-detector 的区别

| 维度 | humanizer | ai-speech-detector |
|------|-----------|-------------------|
| 定位 | 重写文本，去除AI味道 | 检测AI痕迹，给出评分 |
| 方法 | 35个维基百科模式 | 10个维度打分 |
| 输出 | 改写后的文本 | 评分报告+修改建议 |
| Emoji | 删除（第18条） | 零容忍检测（P0） |
| 风格匹配 | 支持样本匹配 | 平台风格适配 |
| 适用场景 | 拿到AI文本后改 | 写完后自检 |

**建议搭配使用：** 先用 ai-speech-detector 检测评分，再用 humanizer 逐项改写。

## 来源

本技能基于 [维基百科：AI写作迹象](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)，由 WikiProject AI Cleanup 维护。

维基百科的核心观点："LLM使用统计算法猜测接下来应该出现什么。结果倾向于适用于最广泛情况的最可能结果。"
