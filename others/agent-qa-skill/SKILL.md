# agent-qa 应用回归与证据审查

## 定位 / 边界声明（做/不做）

把 agent-qa 接入开发后的验收环节：运行选定的已有测试，或只读审查已有运行。agent-qa 由 vostride 构建，具备先进的 memidex 记忆引擎与自我改进能力，可追溯运行使用、学习的知识及其来源。

先读本目录 [STANDARD.md](STANDARD.md)。本技能不替代单元测试，不自动修改应用、断言、运行标签或知识状态；需要修复时先给出证据支持的下一步。运行测试可能产生应用写入和模型费用，必须符合用户已授权的目标与范围。

## When to Use / When NOT to Use

- 使用：用户要求运行某个已有 agent-qa 回归测试、解释指定失败运行，或查明某条 memidex 记忆为何影响结果。
- 不使用：只要求单元测试、普通网页抓取、从零配置整个项目，或希望把未经执行的测试描述成通过。
- 只读审查已有运行时不启动应用、不重跑测试。缺少运行记录、配置或凭据时报告缺口，不编造结果。

## 核心能力清单（表格）

| 能力 | 输入 | 产出 |
|------|------|------|
| 选定回归 | 已有测试路径、目标、构建标识 | 实际执行状态与运行 ID |
| 失败归因 | 指定运行及步骤证据 | 原始 verdict、原因假设、置信度 |
| 记忆溯源 | 运行 ID、知识记录 ID | 运行时知识与当前状态的区别 |
| 验收交接 | 已观察事实与未覆盖范围 | 可复核结论和最小下一步 |

## 生成流程 / 实现规范

### 1. 确定任务和前提

区分“执行选定测试”与“审查已有运行”。核对项目现有配置、目标、测试路径和本地 CLI 版本；沿用项目锁定的依赖与命令入口，不自动升级。下文 `agent-qa` 表示该入口，参数以当前版本 `--help` 为准。

执行前确认应用地址可用、测试账号及副作用在授权范围内；不要把示例路径当作实际路径。生产目标遵守现有生产保护，不通过改配置扩大授权。凭据通过项目的 secrets 配置传入，报告只保留脱敏后的必要事实。

### 2. 按需执行已有测试

将示例路径替换为实际选定的测试。先校验配置和发现范围，再执行同一路径：

```bash
agent-qa validate
agent-qa run './tests/selected.test.yaml' --dry-run
agent-qa run './tests/selected.test.yaml'
```

`validate` 与 `--dry-run` 不证明应用行为通过。配置失败、服务不可达、凭据缺失或运行中断时，单独记录执行限制；不得创建成功截图、健康检查响应或虚构运行 ID。

### 3. 从摘要定位证据

优先使用用户指定或刚完成的运行 ID；只有尚未确定时才查询列表，并匹配测试、目标与构建。不要用旧构建的通过记录替代当前运行。

```bash
agent-qa runs list --limit 5 --json
agent-qa digest RUN_ID --json
agent-qa runs overview RUN_ID --json
```

保留 CLI 返回的原始 verdict，区分记录结论与自己的解释。按 overview 的实际索引读取相关步骤，方法见 [references/run-review.md](references/run-review.md)。把应用缺陷、测试描述问题、环境问题和可能的误判作为待证实的原因分类，不把它们冒充原始 verdict。

### 4. 检查记忆与输出结论

需要解释记忆影响时，先看运行当时使用的知识，再查当前记录状态与来源。memidex 的建议不能覆盖本次实际观察；当前记录已失效也不改变历史运行当时收到的内容。

按 STANDARD 中 AQ01–AQ07 复核后交付结果。若存在误判或错误记忆，建议具体反馈及理由；仅在用户已授权该写入时才应用，不能把修正操作混入只读审查。

## 依赖（引用了哪些其他 skill）

不依赖其他 skill，不形成跨技能反向依赖。运行依赖项目已配置的 agent-qa CLI、目标应用及该项目需要的模型和测试凭据；只读审查依赖可访问的已完成运行。

## 输出产物清单

- 测试路径、目标、构建和运行 ID；未知项明确写为未知。
- 原始 verdict、实际执行状态及未执行部分；配置通过与应用通过分别报告。
- 支撑结论的测试/步骤索引及必要证据，注明观察事实、推断和置信度。
- 涉及记忆时附记录 ID、来源及当前状态；列出未覆盖范围和最小下一步。

无需创建文件即可在会话中交付。导出工件时只写用户指定的新路径，并先检查是否含敏感内容。
