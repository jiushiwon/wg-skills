# payment-skill

支付模块生成器：在已有后端项目上长出完整的微信支付或支付宝支付能力。**只做后端接口，不含前端 UI**。

## 功能

- **渠道**（二选一）：微信支付（Native 扫码 / JSAPI 小程序）或 支付宝（当面付 / WAP 手机网站）
- 统一下单、异步回调验签处理（微信 v3 平台证书 / 支付宝 RSA2）
- 主动查单、主动关单、超时自动关单（先关渠道再改本地）
- 退款（支持部分退款，超额校验）
- 每日对账（渠道账单 vs 本地支付单，差异告警人工介入）

## 使用方式

```
帮我做一个支付模块，微信扫码
现有 Go 项目里对接支付宝支付
加一个支付模块，支持退款
```

技能会先确认渠道（微信/支付宝 单选）、场景、是否有消息队列、是否分账、对账时间等关键决策（都有默认值），然后产出表结构、接口契约增量、目标语言实现和详细对接文档。

## 联动规范

### 与 backend-generate-skill

- 项目无后端骨架时，引导用户先走 backend-generate-skill 生成骨架
- 复用骨架的：统一信封、错误码闭集、JWT 中间件、配置加载、.env 格式
- 追加支付相关环境变量到 `.env.example`

### 与 auth-skill

- 用户表关联：`wg_pay_order.user_id` 关联 `wg_user.id`
- 订单归属从 **Bearer token** 的 `sub` claim 取，不信任客户端传入
- 如项目未接入 auth-skill，默认记录 user_id，不外键强绑

## 模块红线（摘要）

**金额一律整数分（BIGINT），禁止浮点运算；金额不信任客户端，服务端按业务单据重算；回调必须验签（微信 v3 平台证书 / 支付宝 RSA2），禁止跳过验签的开关进生产；渠道调用必须在事务外（本地先提交再调渠道，失败补偿）**。完整红线见 SKILL.md。

## 边界

- **只做后端接口**：不输出前端页面、不做 SDK 封装
- **渠道单选**：微信或支付宝，不可同时接入
- 不做分账、服务商模式、跨境支付、余额/钱包

## 依赖
